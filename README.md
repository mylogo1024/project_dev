# 日常开发工具箱

一个跨平台的日常开发工具集合，基于 Electron + React 开发，支持 Windows、macOS 和 Linux。共 **23 个功能**，涵盖 APK / IPA 安装、包体分析、反编译、DEX 检索、签名、设备管理、投屏与常用文本工具。

> 📷 **界面预览**：见「[界面预览（截图）](#界面预览截图)」，包含设备工作台、命令面板、本机信息等界面截图。

## 功能特性

应用内共有 **23 个功能**，侧边栏按 **4 组**归类：**安装与包体分析** / **文本工具** / **开发工具** / **本机与设置**。
用 `⌘K`（Windows 为 `Ctrl+K`）命令面板或侧边栏搜索可直达任意功能，详见「[使用说明](#使用说明)」。

### 一、安装与包体分析

#### 1. 📦 安装应用（单个 / 批量）　🟡（ADB / ideviceinstaller / Xcode devicectl）

- **单个安装**：选一个 APK / IPA，装到选中的设备；支持覆盖安装
- **批量安装**：一次多选（或整批拖入）多个 APK / IPA，串行装到同一台设备；每个包独立显示「待安装 / 安装中 / 已安装 / 失败 / 已跳过」，列表行内还有自己的进度条
- **整体进度**：把「第 N 个包的 x%」换算成整批百分比，实时显示当前在装哪个包、已耗时，可随时**取消**（会直接 kill 掉正在跑的 adb / ideviceinstaller 进程，剩下的包标记为已跳过）
- **预检**：与目标设备类型不符的包（Android 设备选中 .ipa）和不受支持的文件类型，会在开始前就标成「已跳过」并写明原因，不会等 adb 报错
- **结果汇总**：成功 / 失败 / 跳过数量 + 失败明细，失败原因逐条挂在对应行上
- **平台**：macOS / Windows / Linux 均可运行；iOS 安装链路仅在 macOS 上验证过

#### 2. 📄 读取应用信息（APK / AAB / IPA）　🟢

页面内分「单个包体」与「批量扫描」两个模式，共用同一套纯 JS 解析器，侧边栏只保留这一个入口。两个模式同时挂载、按 CSS 切换，来回切换不会丢掉已经扫出来的结果。

**单个包体模式**

- 支持 APK、AAB、IPA 三种包体格式，可直接把文件**拖到窗口**导入
- **基本信息**（打开即看）：应用图标、名称、包名 / Bundle ID、版本、最低与目标系统、ABI、文件大小与 MD5/SHA-1/SHA-256、签名摘要、权限 / 组件 / 加固四宫格、风险分环形图与 Top 3 风险
- **详细信息**（18 个分类，200+ 字段）：文件与包体结构、应用标识、应用元数据、构建与签名、权限、组件、DEX / 字节码、Native / Mach-O、资源、文件清单、SDK 与框架、安全与风险、隐私与合规、加固与混淆、原始数据；支持分类导航、字段搜索、复制与原始 JSON 查看
- **版本对比**：选择两个包体对比，输出体积差、权限 / 组件 / SDK 增删、签名变更、风险分变化
- **进度与取消**：解析在独立 worker 线程执行，界面不卡顿；分阶段进度条（18~19 个阶段）+ 实时已耗时 + 取消按钮
- **导出 JSON**：完整两层结果一键导出
- **最近打开**：自动记住最近解析过的包体，一键切回

**批量扫描模式**

- 选中一个目录，自动扫描其中所有 APK / AAB / IPA（可含子目录，单次上限 500 个）
- 汇总成一张宽表：应用名、包名 / Bundle ID、版本、体积、最低系统、架构、DEX / SO / 权限 / 组件数量、主要 SDK、加固方案、签名方式、风险分与等级
- **统计概览**：包体总数、解析失败数、平均 / 最高风险分、高危包体数、已加固数、总体积
- **筛选排序**：按风险等级过滤、按风险分 / 体积 / 权限数等排序、关键字搜索
- **导出**：CSV（带 BOM，Excel 直接打开不乱码）/ JSON / Markdown
- 单个包失败不影响整轮扫描，失败原因写进表格；进度显示「第 N / 共 M 个」，可中途停止

- **依赖**：无，纯 JavaScript 实现（`electron/pkginfo/`），无需 aapt / keytool / plutil
- **平台**：macOS / Windows / Linux 三平台完全可用

#### 3. 🔧 反编译 / 回编译 APK / IPA　🟡（APK / AAB 需 apktool；IPA 零依赖）

**APK / AAB**
- 用 apktool 解包成可读目录（资源、清单、smali）
- 自定义输出路径（默认为文件同目录），自动删除同名文件夹
- **依赖**: apktool

**IPA**（不需要任何外部工具）
- **解包**：IPA 本身就是 zip，解压成目录并保留可执行位
- **Mach-O 元数据提取**：从主二进制抽出
  - ObjC **类名**（`__objc_classname`）
  - ObjC **方法名**（`__objc_methname`，已过滤掉属性类型编码这类噪声）
  - **Swift 反射串**（`__swift5_reflstr`）
  - **符号表**（`LC_SYMTAB`）
  - **C 字符串**（`__cstring`，常量的 URL / 密钥常在这里）
- 结果落盘到输出目录的 `_symbols/`（`classes.txt` / `methods.txt` / `symbols.txt` / `strings.txt` / `summary.json`），可直接 grep
- 支持**通用二进制**（fat），会合并各架构后去重

实测某个 0.5MB 的 IPA：**4ms** 提取出 47 个 ObjC 类、1344 个方法、230 个符号。
类名里能直接看出这是 QuickSDK 的扫描器与支付模块；方法名里还能看到被**混淆过的属性名**。

> **边界说明**：这是「元数据提取」，**不是反汇编成源码**。真正的伪代码还原需要
> Hopper / IDA 那类工具，本项目不做也做不到 —— 所以界面上不会把它说成「反编译出源码」。

#### 4. 🔎 DEX 代码检索　🟢

逆向时最高频的两个问题是「这个功能在哪个类」和「这个密钥 / 域名硬编码在哪」。这个工具就干这两件事。

- **类名搜索**：在 APK / AAB 的所有 DEX 里搜类名。`Lcom/a/B;` 会归一化成 `com.a.B`，按人看得懂的形式展示
- **字符串搜索**：搜字符串常量池 —— 找硬编码的 URL、密钥、开关、上报地址
- **包结构概览**：不输关键词时按包聚合，列出每个包有多少个类，点一行即可继续搜该包
- **范围选择**：类名 + 字符串 / 仅类名 / 仅字符串
- **诚实截断**：命中数超过上限时明确提示「还有多少条没显示」，而不是悄悄砍掉
- **结果带出处**：每条都标明来自哪个 `classesN.dex`；类名可一键复制
- **有缓存**：按「路径 + 大小 + mtime」缓存索引，同一个包连续搜走缓存

实测（`csfusion.apk`）：1 个 DEX · 1,564 个类 · 14,181 个字符串，首次解析 33ms；
搜 `https://` 命中 24 条，直接捞出 `https://api-pt.chuangyuejoy.com/` 这类硬编码域名。

- **实现**: `electron/pkginfo/symbols.js`（纯逻辑可单测）+ `src/components/CodeSearch.jsx`
- **限制**: 只支持 APK / AAB（IPA 里没有 DEX，会给出明确提示而不是空结果）

#### 5. ✍️ 应用签名　🟡（apksigner 或 jarsigner）

- 支持 V1 和 V2 签名方式
- 选择签名文件（.jks、.keystore）
- 配置别名和密码（可来自「全局配置」，也可临时填写）
- 自动生成签名后的 APK 文件
- **依赖**: apksigner（Android SDK）或 jarsigner（JDK）

#### 6. 🧪 Dex 工具集　🟡（d8 / dex-tools / baksmali / smali / cfr）

围绕 DEX / JAR / smali 的 7 种转换与反编译，输出文件名统一追加 `_modify` 后缀：

| 操作 | 输入 → 输出 | 用的工具 |
| --- | --- | --- |
| JAR → DEX | `.jar` / `.class` / `.zip` → `.dex` | d8 |
| DEX → JAR | `.dex` / `.apk` → `.jar`（含 `.class`） | dex-tools（d2j-dex2jar） |
| 反编译 JAR | `.jar` / `.class` → Java 源码 | cfr |
| 回编译 JAR | Java 源码 → `.jar` | javac + jar |
| 反编译 DEX | `.dex` / `.apk` → smali 目录 | baksmali |
| 回编译 DEX | smali（文件或目录）→ `.dex` | smali |
| 反编译 ODEX | `.odex` / `.vdex` / `.dex` → 提取内嵌 dex → smali | 内置提取 + baksmali |

- **工具就绪情况**：baksmali / smali / cfr / dex-tools 均为 jar，走 `java -jar`；页面顶部显示每个工具的探测状态，可按需下载
- **进度与取消**：长任务带进度与已耗时，可中途取消
- **附带能力**：查壳（识别加固方案）、启动命令（从同一 APK 读取）

### 二、文本工具

#### 7. 🔤 文本工具　🟢

共 31 个工具，工具栏按「编码 → 解析/生成 → 文本处理 → 查找统计」的顺序排列。

**编码 / 转义（多为即时输出）**

- Base64 编码/解码（支持中文）
- URL 编码/解码
- HTML 实体编码/解码（数字实体、命名实体，`&amp;lt;` 也能正确解成 `&lt;`）
- Unicode 转义/反转义（只转义非 ASCII，中文转成 `\uXXXX`，ASCII 原样保留，结果仍可读；支持 `\u{1f600}` 这类星号平面）
- 十六进制编码/解码（按 UTF-8 字节；解码容忍空格、逗号、`0x` / `\x` 前缀）
- JSON 字符串转义/反转义（处理 `\n` `\t` `\"` 等；单趟扫描，`\\u0041` 不会被解错）
- MD5/SHA1/SHA256 哈希计算

**解析 / 生成**

- **JWT 解码**：拆出 Header / Payload，并把 `iat` / `nbf` / `exp` 转成人话时间，自动判断是否过期（仅解码，不校验签名）
- **URL 参数**：Query ↔ JSON 互转；重复的键合并成数组，整条 URL 也能直接粘进来
- **进制转换**：10/16/2/8 之间互转，逐行处理，某行不合法只标那一行
- **随机生成**：UUID v4 / 强密码 / 随机字符串 / 随机十六进制；输入框填数字可指定长度（密码与随机串排除了 `0O1lI` 这类易混字符）
- 时间戳与日期转换、UUID 生成

**文本处理**

- 大小写/驼峰/下划线/中划线命名转换
- 多行排序（正序/倒序/倒排/去重/去空行）
- **行处理**：加行号 / 去掉行号 / 随机打乱行序 / 反转行序 / 去掉每行首尾空白 / 合并连续空格 / 去掉空行 / 加缩进 / 取消缩进
- **反转文本**：按行反转字符，保留行序（emoji 按码点处理，不会被劈开）
- **去重**：保留首次出现的多行去重

**查找 / 统计**

- **查找**：支持正则、区分大小写、全词匹配；匹配行高亮
- **替换**：查找并替换，支持正则选项
- **行数统计**：总行/空行/非空行/最长/最短/平均行长
- **字数统计**：字符/中文/英文单词/数字/字节
- **对比差异**：两段文本逐行 diff，标出新增/删除/修改
- 底部常驻统计栏（行 | 字符 | 中文 | 单词 | 字节）

#### 8. 📡 HTTP 请求　🟢

- **可视化构造请求**：方法 + URL + Query 参数 / 请求头 / 请求体（JSON / form / raw）三块分开编辑
- **自动解析参数**：往 URL 里粘贴带 `?a=1&b=2` 的地址，或从 URL 框移开焦点，参数会自动拆成逐行表格，
  URL 只留 base（`#fragment` 保留且不会被当成参数值）。发送时会按原样拼回去，最终地址不变
- **参数格式化**：支持粘贴 `a=1&b=2` 或整条 URL 批量解析成行；「整理」去掉空行与重复项、修剪首尾空白；
  「按 key 排序」一键排好；每一行都能单独启用/禁用
- **最终 URL 预览**：参数表下方实时显示真正会发出去的完整地址
- **响应区**：显示状态码、耗时、响应头（可展开），JSON 响应自动美化；返回内容可直接编辑

#### 9. 🧾 JSON 工具　🟢

- **格式化 / 压缩 / 验证**：美化缩进、压成一行、校验格式；校验失败会列出常见的修复方向
- **JSON → Dict / Dict → JSON**：与 Python dict / JS 对象字面量互转。单引号、裸键、`True`/`False`/`None`、
  `#` 与 `//` 注释、尾随逗号都能识别；字符串里的逗号冒号引号不会被误伤
- **中文 → Unicode / Unicode → 中文**：`中文` ↔ `\u4e2d\u6587`（只转非 ASCII，ASCII 原样保留，结果仍可读）
- **添加转义 / 去除转义**：把整段 JSON 转成可嵌入字符串的形式，或还原回来
- **转 Get 参数**：JSON 对象 → `a=1&b=2`，数组展开成重复的键
- **自动纠错**：格式化失败时会先按字典语法救一次（单引号、注释、尾随逗号），救不回来才报错
- **左右分栏 + 全屏查看**：输入输出并排且撑满窗口高度；输出行数多时点「全屏」整屏阅读，Esc 关闭

#### 10. 📝 Markdown 编辑器　🟢

### 三、开发工具

#### 12. 📂 设备文件管理　🟡（ADB / libimobiledevice）

- Android / iOS 双平台，顶部切换设备类型并选择设备
- 浏览设备目录（Android 默认 `/sdcard/`，iOS 默认 `/`），并提供常用路径快捷入口（内部存储、Download、DCIM、`/data/local/tmp` 等）
- **上传 / 下载 / 删除**文件；上传、删除前有确认
- **权限状态提示**：区分 root（已 su）/ 普通权限（shell）/ AFC 媒体分区（未越狱 iOS 不能浏览整机）
- iOS 未越狱时可在「应用文档」中访问单个 App 的 Documents 容器

#### 13. 📱 设备应用管理　🟡（ADB / libimobiledevice）

- 列出设备已安装应用，按 **用户应用 / 全部 / 系统应用** 过滤 + 关键字搜索
- 宽表可**拖动列宽、拖动行高**，列含：应用、包名、版本、APK 大小、缓存、SO 架构、targetSdk、首次安装、更新时间、APK 路径、签名 SHA1 / MD5
- **操作**：导出 APK 到本机 / 卸载 / 清除缓存 / 清除数据（系统应用不能卸载）
- 一键复制包名、Android ID
- iOS：未越狱只能列出与卸载，不能清缓存 / 数据，也不能从设备导出 IPA

#### 14. 📲 连接设备信息　🟡（ADB / libimobiledevice）

- 读取当前 USB 连接的 Android 或 iOS 真机的信息，并可**导出报告**
- **快捷操作**（调用设备自带接口）：
  - **电源**：关机 / 重启 / 息屏 / 亮屏
  - **音量**：静音 / 音量加 / 音量减
  - **导航**：主界面 / 返回 / 最近任务 / 清空后台 / 通知栏
  - **采集**：截图（存 PNG）/ 开始录屏 / 停止录屏（存 MP4）
- 数据只留在本机

#### 15. 🖥️ 设备投屏控制　🟡（Android 需 scrcpy；iOS 仅 macOS）

页面顶部有 **Android / iOS** 两个标签。

**Android**：选设备 → 调最大边长 / 帧率 / 码率 → 点「开始投屏控制」，scrcpy 在独立窗口打开，可用电脑键鼠操作手机（右键 = 返回，中键 = Home）。

**iOS**：

1. 选 iPhone → 点「开始实时显示」
2. 页面有**两套布局**，跟着「方向」切换，让画面在任何方向都尽可能大：

   | 方向 | 布局 | 为什么 |
   | --- | --- | --- |
   | **竖屏**（默认） | **左侧控制栏 + 右侧画面** | 竖屏手机是窄高图，把控制区挪到左边，画面区就能拿到**全部高度** |
   | **横屏** | 控制区在上 + 画面铺满下方 | 横屏画面本来就是宽的，控制区放上面更省地方 |

3. 控制项：缩放（`−` / `+` 或滑块 50%~300%，「适应」贴合窗口，放大后可在画面区内滚动）、竖屏 / 横屏一键旋转 90° 并切换布局、双击画面在 100% / 200% 间切换
4. 「保存画面」按当前方向导出 PNG，「全屏」把画面区铺满屏幕

实测（1200×772 窗口，竖屏）：画面区从 502px 高变成 **601px**，手机画面从 232×502 变成 **278×601**，
占窗口高度的比例从 52% 提到 **78%**。未越狱的 iPhone 只能看不能点，键鼠控制请用 Android scrcpy。

#### 16. 📋 实时日志查看　🟡（ADB / libimobiledevice）

- iOS 日志通过 `libimobiledevice` 的 `idevicesyslog` 获取；当前文档仅说明 macOS 使用与验收，不表示 Windows/Linux 完全支持 iOS 日志

#### 18. 🌐 局域网文件服务　🟢

让手机通过浏览器访问电脑上的文件（`electron/web-file-server.js` + `src/components/WebFileServer.jsx`）。

- 电脑与手机连接同一个可信 Wi-Fi 后，在桌面端选择共享根目录并启动服务；手机打开桌面端显示的地址，或扫描对应二维码。
- 手机端只能在所选根目录内浏览文件与目录、下载文件和上传文件。

**地址与访问令牌：**

- 端口与地址会被记住，**停止再启动仍使用同一个地址**，不会每次随机变化。
- 默认**不启用访问令牌**，地址就是干净的 `http://地址:端口/`，方便在手机上手输或收藏。
- 需要限制访问时，在本页点「启用令牌」。令牌只生成一次并写入本地配置，所以地址在多次启停之间依然固定，形如 `http://地址:端口/?token=…`。
- 服务运行中不能改这项设置，需要先停止服务。

**安全与限制：**

- 服务使用未加密 HTTP，不提供传输加密。**未启用令牌时，同一局域网内任何人只要知道地址就能浏览、下载和上传共享内容**，请只在可信局域网临时使用，不要映射到公网。
- 启用令牌后，拿到完整链接的人即可访问，同样不要转发链接或在公共 Wi-Fi 上启用。
- 无论是否启用令牌，服务都会校验 Host 与 Origin：非本机网段的主机名、跨站来源的写操作都会被拒绝。
- 上传不覆盖已有同名文件；发生重名时拒绝上传，重命名后再试。单个上传文件最大 `2 GiB`，超过限制会被拒绝。
- 符号链接以及 Windows junction（目录联接）会被拒绝，不能借此访问所选根目录之外的位置。
- 系统防火墙提示时，仅允许可信的专用/本地网络。访客 Wi-Fi 常启用客户端隔离，即使 SSID 相同，手机也可能无法访问电脑。

**使用与排查：**
1. 选择根目录，启动服务，在手机上扫描二维码或输入当前地址，再进行浏览、下载或上传。
2. 无法打开时，确认两台设备在同一可信、非访客 Wi-Fi，允许应用通过专用网络防火墙，并关闭可能改写路由的 VPN 后重试。
3. 多网卡时使用与手机同一网段的地址；切换 Wi-Fi、启停 VPN、网卡或 IP 地址变化后，刷新状态并选择当前网段对应的地址。
4. 重名、超过 `2 GiB`、符号链接或 junction 被拒绝属于预期保护，不应通过放宽根目录边界来解决。

#### 19. 🗄️ WebDAV 文件服务　🟢

把选定目录**挂载成「网络磁盘」**，供手机文件 App、Finder、Windows 资源管理器直接读写（`electron/webdav-server.js` + `src/components/WebDavServer.jsx`）。

- **与「局域网文件服务」的区别**：那个只能用浏览器访问、只能浏览与上传下载；WebDAV 可被系统当成网盘**直接读写挂载**。
- **挂载鉴权**：可设置账号 / 密码；**留空即免密挂载**（局域网信任模式，清空密码前会二次确认）。
- **扫码挂载**：页面生成二维码，手机扫码即按当前地址挂载。
- **第三方中转站（异地访问）**：可填 frp / tailscale / 内网穿透等中转地址，二维码与复制提示会切到该地址，方便异地访问。
- **安全与限制**：与局域网文件服务一致，请勿映射到公网；挂载方只能访问所选根目录及其子目录。

#### 20. 🔐 修改文件 Hash　🟢

- 单个文件或批量文件修改 Hash 值
- 支持修改 MD5、SHA1、SHA256 值
- 可以选择多个文件或整个文件夹
- 查看文件当前的 Hash 值
- 通过添加随机字节改变文件 Hash

> **注意**：修改 Hash 会在文件末尾添加随机数据，请提前备份重要文件。

#### 21. ✏️ 文件批量命名　🟢

- **规则可叠加**：扩展名、大小写、顺序编号、替换、插入、截取、重组、片段、随机、移除、删除、列表、自定义模板、正则等，
  按顶部菜单从左到右依次生效，左侧实时预览新旧名与冲突状态
- **随机命名**（「随机」标签页）：
  - **随机字符**：字符集可选 —— 大小写字母+数字 / 仅小写 / 仅大写 / 仅数字 / 十六进制 / **不含易混字符（无 0O1lI）**；长度 1~128
  - **UUID**：标准 v4
  - **随机词库**：完整 NATO 字母表（26 个词），可取 1~5 个词并自定义连接符
  - **随机数字范围**：指定最小 / 最大值
  - **打乱现有文件名**：只重排字符，不改长度
  - 以上都支持加**前缀 / 后缀**（例如 `IMG_` + 随机串 + `_final`）
- **一键「全部随机命名」**：开始页一个按钮，整批文件名直接换成 12 位随机串（保留扩展名、用不含易混字符的字符集），
  批内保证不重名、也不会撞到已有文件；执行前有一次确认，执行后仍可撤销
- **自定义模板新变量**：`%random%` / `%random12%`（指定位数）、`%uuid%`、`%word%` / `%words3%`、
  `%randdate%`（近一年内的随机日期）
- **确定性**：同一个文件每次生成的随机名都相同，所以**预览和真正执行的结果完全一致**

从 Finder 启动的应用不会继承交互式 zsh 的 PATH。应用会主动解析 `/opt/homebrew/bin`（Apple Silicon）、`/usr/local/bin`（Intel）以及系统命令路径，因此不依赖 Finder 提供的终端 PATH；ADB、`libimobiledevice` 等外部工具仍需单独安装，不会被打包进 app。

- **apktool**: 下载 [apktool](https://ibotpeaches.github.io/Apktool/)
- **JDK**: 下载 [OpenJDK](https://adoptium.net/)

#### Linux
```bash
sudo apt install android-tools-adb apktool openjdk-11-jdk
```

Windows 和 Linux 部分维持现有 Android/APK 工具说明；本文不声称 iOS 实时日志在这两个平台完全受支持。

**💡 重要提示**: 如果不使用 APK 安装、反编译、信息读取、签名或实时日志查看，可以跳过对应外部工具；其余不依赖外部命令的功能仍可正常使用。

### 安装应用

**单个安装：**

1. 点击左侧 "安装应用" 按钮
2. 在「设备类型」里选择 Android 或 iOS
3. 点击 "浏览" 选择要安装的 APK / IPA（也可以直接把文件拖到输入框里）
4. 在 "目标设备" 下拉框中选择设备（如果没有显示设备，点击 "刷新设备"）
5. 点击 "安装到 Android / iOS 设备"，过程中会显示进度条与已耗时

**批量安装：**

1. 切换到顶部的 "批量安装" 标签页
2. 点击 "添加文件" 一次多选 APK / IPA，或把多个文件一起拖到列表区域；重复的文件会自动去重
3. 与当前设备类型不符的包会以黄色标出「与目标设备不符，将被跳过」，可点 "仅保留可安装的 N 个" 一键清理
4. 确认目标设备后点击 "批量安装（N 个）"——包会**串行**安装（设备同一时刻只能装一个）
5. 列表里每一行实时显示自己的状态与进度；整体进度条显示当前是第几个包、已耗时多少
6. 需要中断时点 "取消"，正在跑的安装会被终止，未开始与未完成的包标记为「已跳过」
7. 全部结束后查看成功 / 失败 / 跳过汇总，失败原因直接显示在对应行上

### 反编译 APK / IPA

1. 点击左侧 "反编译 APK / IPA" 按钮
2. 选择 APK / AAB / IPA 文件
3. 选择或输入输出目录（默认为 APK 所在目录）
4. 点击 "开始反编译"
5. 反编译完成后会在输出目录生成以 APK 名称命名的文件夹

### 读取应用信息

1. 点击左侧 "读取应用信息" 按钮，页面顶部有 **单个包体 / 批量扫描** 两个模式标签

**单个包体模式**

1. 选择要读取的 APK / AAB / IPA 文件（也可以直接把文件拖到输入框里；最近打开过的文件会列在下方，一键切回）
2. 点击 "读取信息" —— 解析过程中会显示**分阶段进度条**（当前阶段、正在处理的文件、已耗时），随时可以点「取消」
3. 默认进入**概览页**：应用图标与名称、包名 / Bundle ID、版本、最低与目标系统、ABI、文件大小与哈希、签名摘要、权限 / 组件 / 加固四宫格、风险分环形图与 Top 3 风险
4. 点击 "详细信息" 切换到**详情页**：左侧 18 个分类导航，右侧字段表 / 表格 / 文件树；顶部可搜索当前分类的字段与取值，也可复制该分类 JSON
5. 点击 "导出 JSON" 将完整两层结果保存为文件
6. 在对比栏选择另一个版本的包体并点击 "开始对比"，可查看体积、权限、组件、SDK、签名与风险分的差异

**批量扫描模式**

4. 扫描完成后查看统计概览与宽表：应用名、包名、版本、体积、最低系统、架构、DEX / SO / 权限 / 组件数、主要 SDK、加固方案、签名方式、风险分
5. 用风险等级按钮过滤，点击表头（风险分 / 体积 / 权限数 / 组件数 / SDK 数）排序，或搜索文件名 / 应用名 / 包名 / SDK
6. 点击任意一行展开该包的完整字段；点击 "导出 CSV / JSON / Markdown" 保存结果

**提示：** 单个包解析失败不会中断整轮扫描，失败原因会写在表格的「解析错误」列里。CSV 带 UTF-8 BOM，Excel 双击打开不乱码。

   - **缩放**：`−` / `+` 或拖动滑块（50% ~ 300%）；「适应」回到贴合窗口；放大超过 100% 后可在画面区内滚动查看
   - **竖屏 / 横屏**：一键把画面旋转 90°，同时切换上面那两套布局
   - 双击画面在 100% / 200% 之间快速切换
4. "保存画面" 会按当前方向导出 PNG，"全屏" 把整个画面区铺满屏幕

实测（1200×772 窗口，竖屏）：画面区从 502px 高变成 **601px**，手机画面从 232×502 变成 **278×601**，
占窗口高度的比例从 52% 提到 **78%**。未越狱的 iPhone 只能看不能点，键鼠控制请用 Android scrcpy。

## 常见问题

### Android 设备列表为空

**可能原因：** ADB 未安装、USB 调试未开启，或设备尚未授权。

**排查方法：**
- 确保 ADB 已安装；应用从 Finder 启动时也会主动查找 Homebrew 和系统命令路径
- 解锁 Android 设备，通过 USB 连接电脑并开启“开发者选项”和“USB 调试”
- 接受设备上的 USB 调试授权提示
- 在终端运行 `adb devices`；若状态为 `unauthorized`，重新确认授权后刷新设备列表

### iOS 设备列表为空或无法捕获日志

**可能原因：** `libimobiledevice` 未安装，iPhone 未解锁、未信任或未完成配对。

**排查方法：**
- macOS 运行 `brew install libimobiledevice`，然后运行 `idevice_id -l` 检查是否能发现设备
- 解锁 iPhone，使用 USB 连接 Mac，并在 iPhone 上确认“信任此电脑”
- 使用 `ideviceinfo -u <UDID>` 检查配对和设备信息；将 `<UDID>` 替换为实际设备标识
- 使用 `idevicesyslog -u <UDID> --no-colors -x` 对照检查系统日志能否输出
- 应用从 Finder 启动时不继承交互式 zsh 的 PATH，但会主动解析 `/opt/homebrew/bin`、`/usr/local/bin` 和系统路径；外部工具不会打包进 app

### iPhone 投屏报 “Requested device not found” / 画面一直出不来

**原因：** macOS 上的 iOS 实时画面走 AVFoundation 采集设备，本机必须真的存在一个视频输入源（内置摄像头，或 QuickTime 激活出来的 iPhone 屏幕设备）。Mac mini / Mac Studio / Mac Pro 没有内置摄像头，AVFoundation 也不会凭空产生 iPhone 采集设备，此时 `getUserMedia` 会直接抛 `NotFoundError: Requested device not found`。

**排查方法：**
- 先确认本机到底有没有采集设备：
  - `system_profiler SPCameraDataType` 输出为空数组 → 本机无摄像头
  - `ffmpeg -f avfoundation -list_devices true -i ""` 只列出 `Capture screen 0/1` → 没有 iPhone 采集设备
- 若有内置摄像头，打开 **QuickTime Player → 文件 → 新建影片录制**，点录制按钮旁的小箭头选择 iPhone，激活一次采集通道，再回工具里点「刷新画面源」
- 本机确实没有采集设备时，工具会自动退回到 **截图刷新模式**（依赖 `idevicescreenshot`，实测约 1 帧/秒），可用于看界面和状态，不适合看视频
- 截图模式要求 iPhone 已解锁并「信任此电脑」；单张截图约 1 秒，属正常现象
- 界面顶部的能力提示条会直接写明本机是否检测到采集设备，可据此判断走的是实时采集还是截图刷新

### 投屏中途报 “No device found with udid …”

**原因：** 这是**截图刷新模式下的瞬时故障**，不是配置问题。`idevicescreenshot` 在以下情况都会输出这句话（注意它打在 stdout 上，退出码 255）：

- iPhone 自动锁屏了 —— 截图服务需要设备处于解锁状态
- 数据线松动 / USB 链路被系统挂起
- 设备真的被拔掉了

**工具会怎么处理：**

- 立刻查一次 `idevice_id -l` 来区分「拔了」还是「锁屏 / 链路抖动」，给出对应的中文提示，不会把原始英文错误丢给你
- 连续失败时**自动退避**（0.6s → 1s → 2s → 3s 封顶），不再每 600ms 死磕一个不可用的设备
- **解锁手机或重新插好线后会自己恢复**：画面继续刷新，红色报错自动消失并退回正常提示

**如果一直不恢复：**

```bash
idevice_id -l                                    # 设备还在不在
idevicescreenshot -u <UDID> /tmp/shot.png        # 单独跑一次看真实报错
```

- 两条都正常但界面仍不刷新 → 点「停止投屏」再点「开始实时显示」重建会话
- `idevice_id -l` 为空 → 换根数据线或换 USB 口，iPhone 上重新确认「信任此电脑」

### 反编译失败

**原因：** apktool 未安装

**解决方法：**
- 安装 apktool：`brew install apktool` (macOS/Linux)
- Windows 用户下载 apktool.bat 和 apktool.jar

### 签名失败

**原因：** apksigner 或 jarsigner 未安装

**解决方法：**
- 确保已安装 JDK（包含 jarsigner）
- 或安装 Android SDK Build Tools（包含 apksigner）

### 读取应用信息失败

**原因：** 文件不是有效的 APK / AAB / IPA，或包体结构损坏（例如 ZIP 中央目录缺失、AndroidManifest.xml 无法解析）

**解决方法：**
- 确认文件扩展名与真实格式一致（`.apk` / `.aab` / `.ipa`）
- 确认文件完整、未被截断
- 若是加固包且部分字段为空，属正常现象：加固会加密 DEX 与 Manifest 中的字符串，部分信息无法静态还原，界面会在结果中给出警告提示

> 说明：读取应用信息已改为纯 JavaScript 实现，**不再需要安装 aapt / keytool / plutil**。

### 局域网文件服务：一台手机能访问，另一台不行

**先看「最近访问」面板**（局域网文件服务页底部，展开后点「刷新状态」）：在连不上的那台手机上打开访问地址，然后回来刷新。

- **列表里出现该手机的 IP** → 请求到了电脑，是服务端在拒。看状态码：`4xx` 说明地址或来源校验没过（通常是手机用了列表里另一个地址）
- **列表里始终没有它** → 请求根本没到电脑，是网络问题，与工具无关

**排查方法：**

- **确认两台设备在同一个局域网**：手机 Wi-Fi 是否连的是同一 SSID、同一频段；关掉手机上的 VPN / 加速器（会让流量绕到外网，反而回不到内网 IP）；关掉「移动数据」，避免走蜂窝
- **路由器可能开了「AP 隔离 / 客户端隔离」**：开启后同一 Wi-Fi 下的设备之间不能互访，表现就是「电脑自己能开、手机连不上」
- **macOS 防火墙**：系统设置 → 网络 → 防火墙，确认没有拦截本应用；弹过「是否允许接受传入连接」时要选允许
- 在电脑上确认服务本身是好的（把 `<端口>` 换成应用里显示的端口）：

  ```bash
  curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:<端口>/api/files   # 期望 200
  ```

**关于地址列表：** 每个地址都标了它是**哪块网卡**，手机该用哪条取决于**它自己接在哪**：

| 标签 | 地址形态 | 什么时候用 |
| --- | --- | --- |
| Wi-Fi（无线） | `192.168.x` 等 | 手机连的是同一个 Wi-Fi |
| 以太网（有线） | `192.168.x` 等 | 手机连的网络和电脑插的网线互通 |
| USB 直连 / 链路本地 | `169.254.x` | 手机通过 USB 直连（典型是 iPhone 的 USB 网络）。**这条是真能用的**，别以为是坏地址 |

**注意一台电脑可能同时接好几个互不相通的网络。** 实测见过：有线 `192.168.8.x` + Wi-Fi `192.168.35.x`，
手机连 Wi-Fi 就只能用标着「Wi-Fi」的那条。只写「局域网」而不写哪块网卡，根本没法选。

IPv6 链路本地（`fe80::`）会被自动过滤掉 —— 没有 zone id 时写成 URL 浏览器根本解析不了，
一台多网卡的 Mac 以前会因此列出十几个条目。

> 注意 `169.254.x` 会随链路重新协商而变化，所以别把它抄下来长期用；每次都从页面上取当前地址。

### 点「复制」提示 Write permission denied

**原因：** `navigator.clipboard.writeText()` 申请的是 `clipboard-sanitized-write` 权限。Electron 的
`setPermissionRequestHandler` / `setPermissionCheckHandler` 用的是白名单，**没列进去就等于拒绝**，
渲染层收到的是 `NotAllowedError: Write permission denied.`。

**已修复**：`electron/main.js` 的 `ALLOWED_PERMISSIONS` 里已加入 `clipboard-sanitized-write` 与 `clipboard-read`。
应用里十几处「复制」按钮（复制访问地址、复制字段、复制 JSON、复制日志…）都依赖它，所以这个问题会一次性影响全部复制功能。

**注意区分两种报错：**

| 报错 | 含义 |
| --- | --- |
| `Write permission denied.` | 窗口有焦点，但**权限被拒** → 查权限白名单 |
| `Document is not focused.` | 窗口没焦点，Chromium 直接拒绝 → 点一下窗口再复制即可 |

**排查方法：** 在窗口里打开 DevTools，执行 `await navigator.clipboard.writeText('x')`，看抛的是哪一个。
`electron/main.js` 里给两个 handler 都加上对应权限名即可（两个都要加，只加一个不稳）。

### 解析大包时进度条停在某个阶段不动

**原因：** 该阶段本身耗时较长。DEX 解析、代码字符串扫描、风险规则匹配在 200 MB 级的加固包上各需要 1~3 秒。

**解决方法：**
- 进度条右侧的「已用 X 秒」会持续更新，只要它在走就说明解析正常
- 确实想中断时点进度条上的「取消」，会立即终止 worker 线程
- 解析跑在独立线程里，即使耗时较长也不会卡住界面，可以正常拖动窗口

### 批量扫描没有扫到任何包体

**可能原因：** 包体在子目录里但没勾选「包含子目录」；或目录里确实没有 `.apk` / `.aab` / `.ipa` 文件。

**解决方法：**
- 勾选「包含子目录」后重新扫描
- 确认文件扩展名正确（大小写不敏感）
- 单次上限 500 个，超出部分不会被扫描

### 拖拽文件到窗口没反应 / 窗口变成白屏

**解决方法：**
- 拖拽目标必须落在输入框所在的虚线区域（区域会高亮）
- 若拖拽后窗口白屏，说明该文件被拖到了区域之外。这是 Electron 的默认行为（导航到 `file://`），应用已在入口统一拦截，如仍出现请提 issue
- 取不到文件真实路径时（个别系统安全策略），改用「浏览」按钮选择

### 打包失败

**原因：** 缺少图标文件或配置错误

**解决方法：**
- 确保配置中引用的 `build/icon.icns`、`build/icon.ico` 和 `build/icon.png` 存在
- 检查 `package.json` 中的 electron-builder 配置

2. 反编译 APK 时会删除同名文件夹，请提前备份重要数据
3. 某些受保护的 APK 可能无法反编译
4. 签名时请确保签名文件和密码正确
5. 打包前确保 `npm run build` 成功执行
